# 모아

여행지와 음식을 정할 때 각자의 좋은 조건과 피하고 싶은 조건을 버튼으로 선택하고, 균형 있는 후보를 실시간으로 확인하는 브라우저 앱입니다.

## 실행

정적 호스팅(Vercel 등)에 폴더를 배포하거나 HTTPS로 제공하면 브라우저에서 사용할 수 있습니다. PWA 설치와 오프라인 실행은 `file://`로 직접 열 때는 동작하지 않습니다.

## PWA 설치

- Android: Chrome에서 배포 URL을 연 뒤 메뉴에서 `앱 설치` 또는 `홈 화면에 추가`를 선택합니다.
- iPhone/iPad: Safari에서 배포 URL을 연 뒤 공유 메뉴에서 `홈 화면에 추가`를 선택합니다.
- 앱 셸은 서비스워커가 캐시하고, 참여자와 선호 설정은 이 브라우저의 IndexedDB에 저장합니다. IndexedDB를 쓸 수 없는 경우에만 localStorage로 대체합니다.
- 브라우저와 홈 화면 앱은 서로 다른 저장 공간을 쓸 수 있으므로 `백업 다운로드`와 `백업 복원`으로 설정을 옮길 수 있습니다.
- 서비스워커 업데이트는 안내 배너의 `업데이트`를 눌렀을 때 적용됩니다.

Vercel에서는 `vercel.json`이 HTML, manifest, 서비스워커를 재검증하도록 설정합니다. 앱 경로와 에셋 참조는 상대 경로를 사용합니다.

## GitHub Pages 배포

`.github/workflows/deploy-pages.yml`은 `main` 브랜치에 push될 때 정적 앱을 GitHub Pages에 게시합니다.

1. GitHub에서 새 저장소를 만들고 이 앱 폴더의 파일을 `main` 브랜치에 push합니다.
2. 저장소의 `Settings` → `Pages`에서 Build and deployment source를 `GitHub Actions`로 선택합니다.
3. `Actions` 탭에서 `Deploy static PWA to GitHub Pages` 작업이 성공하면 화면에 표시된 Pages 주소를 엽니다.
4. 이후 `main`에 push할 때마다 자동으로 다시 배포됩니다. 저장소 공개 여부와 Pages 사용 가능 여부는 GitHub 계정 요금제·조직 정책에 따릅니다.

앱 자산·manifest·서비스워커 URL은 상대 경로라 `https://<계정>.github.io/<저장소>/` 같은 프로젝트 하위 경로에서 동작하도록 구성되어 있습니다. 공개 HTTPS 주소가 생기면 휴대폰에서도 설치할 수 있습니다.

## 계산 방식

현재 버전은 외부 AI/API 없이 동작하는 태그 기반 프로토타입입니다. 선택한 선호와 후보 특성을 비교해 모두의 만족이 고르게 반영되는 순서로 추천합니다. 피하고 싶은 조건은 좋은 조건보다 우선적으로 고려합니다. 선호를 바꾸면 추천 순서와 후보별 최종 균형 점수가 즉시 갱신됩니다. 키워드별 점수와 개인별 세부 점수는 표시하지 않고 추천 이유를 보여줍니다.

여행지는 전국 26개 지역, 음식은 한식·일식·중식·이탈리안·멕시칸·태국식·비건 등 31가지 메뉴를 포함합니다. 상위 추천부터 확인하거나 전체 후보를 펼쳐 볼 수 있습니다. 한 사람의 큰 불만이 다른 사람들의 작은 선호에 묻히지 않도록 설계했습니다.

실제 자연어 AI 연동이나 여러 기기 간 공유에는 별도의 서버/API 연결이 필요합니다.
